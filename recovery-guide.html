Panduan pemulihan IPCOS

Cadangan harian berada dalam folder IPCOS - Cadangan Privat di Drive pemilik backend. Folder ini tidak dibagikan oleh aplikasi. Administrator website yang tidak memiliki akses Drive perlu menghubungi pemilik backend.

Periksa cadangan

  1. Di menu admin, buka Cadangan dan pemulihan. Pastikan status Cadangan lengkap dan waktu cadangan sesuai.
  2. Buka folder cadangan. Di dalamnya ada salinan spreadsheet Database IPCOS, manifest.json, dan salinan dokumen. Manifest mencatat ID dokumen asli dan ID salinannya.
  3. Jika status sebagian atau gagal, periksa log eksekusi Apps Script. Jangan menganggap semua berkas tersedia sampai daftar kesalahan kosong. Proses berkas dilanjutkan setiap 10 menit.

Pulihkan dengan pemeriksaan terlebih dahulu

  1. Tutup sementara penerimaan pengajuan baru melalui pengaturan periode. Koordinasikan penghentian sementara tindakan admin dan revisi mahasiswa agar tidak ada transaksi selama pemulihan.
  2. Cadangkan kondisi database terbaru sebelum mengubah apa pun. Pertahankan seluruh cadangan lama.
  3. Buat salinan kerja dari cadangan yang dipilih. Periksa sheet Mahasiswa, Registrasi, DataDosen, Pengumuman, dan KontenWeb. Pertahankan nama sheet dan susunan kolom.
  4. Untuk dokumen yang hilang, gunakan pasangan originalId dan copyId pada manifest. Perbarui tautan dokumen yang dipulihkan di kolom link dan metadata dokumen dalam riwayat note pada salinan kerja. Jangan hanya mengganti tautan di satu tempat.
  5. Bandingkan kuota dosen dengan pengajuan diterima. Pastikan identitas mahasiswa dan status pengajuan benar. Uji akses dokumen dengan akun yang memang berhak; jangan membuka seluruh folder cadangan kepada publik.
  6. Pemilik backend dapat memulihkan data dari salinan yang diverifikasi ke spreadsheet asli dengan mempertahankan struktur dan skrip terikatnya. Perubahan ID spreadsheet saja tidak cukup karena backend memakai spreadsheet terikat aktif. Lakukan tahap ini dengan pendamping teknis.
  7. Pengaturan periode dan target ada dalam manifest. Masukkan kembali melalui panel admin jika diperlukan. Cara login dan kredensial tidak disimpan dalam manifest.
  8. Uji login kedua peran, rincian pengajuan, revisi, persetujuan, kuota, serta unduhan bukti dengan data uji sebelum membuka layanan kembali.

Jika masalah berasal dari rilis kode

Gunakan deployment Vercel sebelumnya untuk antarmuka dan versi deployment Apps Script sebelumnya untuk backend. Pastikan keduanya sesuai sebelum mengaktifkan layanan. Pemulihan kode tidak otomatis memulihkan data.

Jadwal dan penyimpanan

Cadangan dijadwalkan setiap hari sekitar pukul 04.00 WIB. Berkas disalin bertahap untuk menghindari batas waktu eksekusi. Cadangan tidak dihapus otomatis. Pemilik perlu memeriksa kapasitas Drive dan menyimpan cadangan penting terpisah secara berkala.
